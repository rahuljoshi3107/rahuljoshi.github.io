Workflow

From org to deployment
in four steps

SF Release Tracker fits naturally into your existing Salesforce workflow — zero configuration required.

1

Open Salesforce

Navigate to any Salesforce org in Chrome — Lightning, Classic, Visualforce, or Setup all work.

2

Connect & Create Release

Click the extension icon. Your session is auto-detected. Create a named release like "Sprint-Q2-2026".

3

Fetch & Select

4

Generate & Export

Generate package.xml, add pre/post steps, write deployment notes, and export your full workbook.

Privacy & Security

Privacy
by design.

SF Release Tracker was built with a zero-data-collection policy from day one. Your Salesforce credentials, components, and deployment data never leave your device.

The extension connects directly to your Salesforce org using your existing browser session cookie — the same way you're already logged in. No additional OAuth app or credentials required.

💾
Local Data Only
All data in chrome.storage.local. Nothing sent to external servers.
🚫
No Third-Party Sharing
Zero data shared with analytics, advertising, or any third-party service.
📋
No Data Collection
No telemetry, no crash reports, no usage tracking of any kind.
🛡️
Minimal Permissions
Only cookies (SID read), scripting, and sidePanel — the bare minimum.
Installation

Up and running
in under 2 minutes

Install directly from the Chrome Web Store. No configuration, no CLI, no setup required.

🔌
Install from Chrome Web Store
Free · Manifest V3 · Works on all Salesforce domains
1

Visit the Chrome Web Store

Search for SF Release Tracker or click the Install button below to go directly to the listing.

2

Click "Add to Chrome"

Accept the permissions prompt. The extension needs access to Salesforce domains and your session cookie to detect your org automatically.

3

Open Salesforce & click the icon

Navigate to your org (e.g. yourorg.lightning.force.com), click the SF Release Tracker toolbar icon, and the sidebar opens. For first-time use, refresh the Salesforce page once before clicking Connect.

4

Create a release and start fetching

Click + New Release, give it a name, then click Fetch Changes. Your modified components load instantly — filtered to your changes by default.

FAQ

Common questions

Quick answers to the most common questions about SF Release Tracker.

Does SF Release Tracker work on sandboxes and scratch orgs?+
Yes. SF Release Tracker works on any Salesforce org accessible via a supported domain — including sandboxes (*.sandbox.my.salesforce.com), scratch orgs, developer editions, and production. It auto-detects the org from your active browser tab.
Is my session token ever sent anywhere?+
Never. Your session token (SID) is read from your browser's cookie store and used only to call Salesforce's own APIs directly from your browser. It is never transmitted to any external server, logged, or stored outside chrome.storage.local.
Can I use SF Release Tracker without an internet connection?+
Partially. package.xml generation, destructiveChanges.xml, checklist management, deployment notes, and Excel export all work fully offline. Only Fetch Changes requires an active Salesforce session to call the Tooling API and REST API.
What happens to my releases when I switch orgs?+
Releases are bound to their org by Org ID. When you switch orgs, SF Release Tracker automatically surfaces the most recently updated release for that org. All your previous releases are preserved and return when you switch back.
Can I add metadata types not in the auto-fetch list?+
Yes. Click + Add manually in the Components tab to add any Salesforce metadata type — Layout, FlexiPage, CustomMetadata, Report, Dashboard, ConnectedApp, and many more. They're included in your package.xml just like auto-fetched components.
The extension isn't connecting — what should I do?+
Make sure you have an active Salesforce tab open and are logged in. On first install, refresh your Salesforce tab once before clicking Connect. If it still doesn't work, try clearing your browser cache or reloading the extension at chrome://extensions.
